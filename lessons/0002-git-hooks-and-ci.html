Lesson 0002 · Repository quality gates

Every gate between your keyboard and main

A change in this repo passes up to five gates: three git hooks on your machine (pre-commit, commit-msg, pre-push), the CI workflow on GitHub, and a set of scheduled bots. Click a gate to open what it runs, what it checks, and the real source lines that do it.

New in this change Pre-commit now runs scripts/quality/check-dependabot.mjs. It fails when a package.json, composer.json, Dockerfile or workflow is not watched by .github/dependabot.yml. It also runs the same vulnerability audit as CI's security job for any lockfile staged in that commit. Jump to it.
Found while building this On 2026-10-24, npm audit --omit=dev --audit-level=high fails in dashboard (5 high, e.g. zod, source-map-js) and payment-server (3 high, 1 critical, e.g. proxy-addr, qs). composer audit passes. So CI's security job fails today. The new hook will also block any commit that stages one of those two lockfiles until npm audit fix (or a Dependabot PR) clears them.

Six words first

WordPlain meaning
Git hookA script git runs on its own at a fixed moment, such as just before it records a commit. If the script exits non-zero, git stops.
HuskyAn npm package that points git at the .husky/ folder, so the hook scripts live in the repo and everyone gets the same ones.
Staged filesThe files you git add-ed: what the next commit will contain.
lint-stagedRuns a linter on only the staged files, not the whole project.
CI jobOne isolated task on a fresh GitHub machine. Jobs run in parallel unless one needs another.
DependabotGitHub's bot. It reads .github/dependabot.yml, then opens PRs that bump outdated or vulnerable dependencies.

Step 0: how the hooks get installed

npm install at the repo root runs the prepare script. That runs .husky/install.mjs, which calls Husky. Husky sets core.hooksPath to .husky/_, and git then finds the hooks there. CI and production builds skip this step, because nobody commits from those machines.

L33 · Dependabot gate (new)

Dependabot only watches the folders listed in .github/dependabot.yml. If you add a service with its own package.json and forget that file, nothing tells you. The service never gets update or security PRs. This gate catches that before the commit lands.

  • L16-L24 audits: only when that lockfile is staged. It runs the same commands as CI's security job: npm audit --omit=dev --audit-level=high (production deps, high or critical only) and composer audit --locked. These need the network.

The matching logic lives next to the other path rules, so npm run quality:test can test it:

scripts/quality/project-map.mjs:L65-L98

const manifestEcosystems = [
  [/(^|\/)package\.json$/, 'npm'],
  [/(^|\/)composer\.json$/, 'composer'],
  [/(^|\/)Dockerfile(\.[\w-]+)?$/, 'docker'],
  [/^\.github\/workflows\/[^/]+\.ya?ml$/, 'github-actions'],
]

// ponytail: line-based read of dependabot.yml; switch to the yaml package if the config grows anchors or flow lists
export function dependabotEntries(config) {
  const entries = new Set()
  let ecosystem
  for (const line of config.split(/\r?\n/)) {
    const ecosystemMatch = line.match(/^\s*-\s*package-ecosystem:\s*['"]?([\w-]+)/)
    if (ecosystemMatch) ecosystem = ecosystemMatch[1]
    const directoryMatch = line.match(/^\s*directory:\s*['"]?([^'"\s#]+)/)
    if (directoryMatch && ecosystem) entries.add(`${ecosystem}:${directoryMatch[1].replace(/\/$/, '') || '/'}`)
  }
  return entries
}

export function dependabotCoverageGaps(config, files) {
  const covered = dependabotEntries(config)
  const gaps = new Set()
  for (const file of files) {
    // ponytail: dot-directories other than .github hold vendored agent tooling, not shipped code
    if (/^\.(?!github\/)/.test(file)) continue
    for (const [pattern, ecosystem] of manifestEcosystems) {
      if (!pattern.test(file)) continue
      const directory = ecosystem === 'github-actions' ? '/' : `/${path.posix.dirname(file)}`.replace(/^\/\.$/, '/')
      if (!covered.has(`${ecosystem}:${directory}`)) gaps.add(`${ecosystem}:${directory}`)
    }
  }
  return [...gaps]
}

L90 skips dot-folders other than .github, such as .agents/skills/archify/package.json, which is vendored agent tooling. L93 maps package.json at the root to /, and maps every workflow file to /, because that is where Dependabot looks for Actions.

L34 · per-project checks

First the staged paths are sorted into projects. Then each touched project runs its full gate. Changing anything under .github/, scripts/quality/ or commitlint.config.cjs sets all, which runs every project.

export function classifyFiles(files) {
  const normalized = files.filter(Boolean).map((file) => file.replace(/^\.\//, ''))
  const projects = new Set()
  let docker = false
  let api = false
  let all = false
  let dbSchema = false

  for (const file of normalized) {
    if (matches(file, 'crm-server') || matches(file, 'docker/crm-server')) projects.add('crm')
    if (matches(file, 'dashboard') || matches(file, 'docs/openapi') || matches(file, 'docker/dashboard')) projects.add('dashboard')
    if (matches(file, 'payment-server') || matches(file, 'docker/payment-server')) projects.add('payments')
    if (
      rootFiles.has(file) ||
      matches(file, 'docker/nginx') ||
      matches(file, 'docker/postgres') ||
      matches(file, 'docker/redis') ||
      matches(file, 'docker')
    ) docker = true
    if (
      matches(file, 'docs/openapi') ||
      matches(file, 'dashboard/scripts') ||
      file === 'dashboard/public/openapi.json' ||
      matches(file, 'dashboard/src/api/generated') ||
      matches(file, 'crm-server/routes/api') ||
      matches(file, 'crm-server/app/Http')
    ) api = true
    if (file.startsWith('.github/') || file.startsWith('scripts/quality/') || file === 'commitlint.config.cjs') all = true
    if (
      matches(file, 'crm-server/database/migrations') ||
      matches(file, 'payment-server/src/database/migrations') ||
      file === 'payment-server/src/database/data-source.ts' ||
      matches(file, 'scripts/quality/db-schema') ||
      file === 'scripts/quality/generate-db-schema.mjs' ||
      matches(file, 'docs/db')
    ) dbSchema = true
  }

  if (all) {
    projectNames.forEach((project) => projects.add(project))
    dbSchema = true
  }
  return { files: normalized, projects: [...projects], docker, api, all, dbSchema }
}

scripts/quality/git-files.mjs:L14-L19

export function rangeFiles(from, to) {
  if (!from || !to) return []
  const emptyTree = '4b825dc642cb6eb9a060e54bf8d69288fbee4904'
  const base = /^0+$/.test(from) ? emptyTree : from
  return gitFiles(['diff', '--name-only', '--diff-filter=ACMR', `${base}..${to}`])
}
  • git-files L17: when you push a brand-new branch, the remote hash is all zeros. The diff then starts from git's empty tree, so every file in the pushed commits counts as changed.
  • push-check L14-L15: production builds: tsc -b && vite build for the dashboard and nest build for payments, only if those projects changed. The builds catch errors that type-checking alone misses.
  • L17: Docker structure and Compose validation, always.
  • L19-L21: API contract drift, always. api:docs:check regenerates the OpenAPI JSON in a temp dir and diffs it against the committed one. api:check does the same for the generated TS types.

policy-gate: the one check branch protection needs

This runs always(), even after a failure, and fails if any listed job ended with anything other than success or skipped. Path-filtered jobs that skip count as a pass. Branch protection then only needs to require this one job.

.github/workflows/ci.yml:L521-L569

  policy-gate:
    name: CI policy gate
    if: ${{ always() }}
    needs:
      - workflow-policy
      - security
      - changes
      - commit-policy
      - api-docs
      - docker-structure
      - crm
      - dashboard
      - payments
      - db-schema
      - compose
      - crm-image
      - dashboard-image
      - payments-image
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    steps:
      - name: Enforce required checks
        shell: bash
        run: |
          set -euo pipefail
          required=(
            'workflow-policy:${{ needs.workflow-policy.result }}'
            'security:${{ needs.security.result }}'
            'changes:${{ needs.changes.result }}'
            'commit-policy:${{ needs.commit-policy.result }}'
            'api-docs:${{ needs.api-docs.result }}'
            'docker-structure:${{ needs.docker-structure.result }}'
            'crm:${{ needs.crm.result }}'
            'payments:${{ needs.payments.result }}'
            'db-schema:${{ needs.db-schema.result }}'
            'compose:${{ needs.compose.result }}'
            'crm-image:${{ needs.crm-image.result }}'
            'dashboard:${{ needs.dashboard.result }}'
            'dashboard-image:${{ needs.dashboard-image.result }}'
            'payments-image:${{ needs.payments-image.result }}'
          )
          for check in "${required[@]}"; do
            name=${check%%:*}
            result=${check#*:}
            if [[ "$result" != 'success' && "$result" != 'skipped' ]]; then
              echo "$name ended with $result" >&2
              exit 1
            fi
          done

codeql.yml: static security analysis

This runs on PRs, on pushes to main and dev, and every Monday at 04:23 UTC. It scans JavaScript/TypeScript only, because CodeQL does not support PHP (see the comment on L27). Findings go to the repo's Security tab.

.github/workflows/codeql.yml:L1-L44

name: CodeQL

on:
  pull_request:
  push:
    branches: [main, dev]
  schedule:
    - cron: '23 4 * * 1'
  workflow_dispatch:

permissions:
  contents: read
  security-events: write

concurrency:
  group: codeql-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  analyze:
    name: Analyze ${{ matrix.language }}
    runs-on: ubuntu-24.04
    timeout-minutes: 20
    strategy:
      fail-fast: false
      matrix:
        # GitHub recognizes PHP as a repository language, but CodeQL does not scan PHP.
        language: [javascript-typescript]
    steps:
      - name: Check out source
        uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7

          persist-credentials: false

      - name: Initialize CodeQL

          languages: ${{ matrix.language }}

      - name: Analyze code
        uses: github/codeql-action/analyze@f3712979fa5f215279b101dd0a2e3bdfb4353324 # v3
        with:
          category: /language:${{ matrix.language }}

On every push to main, it reads the Conventional Commit types since the last release. It then opens or updates a release PR that bumps VERSION and the manifest and writes CHANGELOG.md. This is why gate 2 exists. It is the only workflow with write permissions.
