Plain-English dictionary

TermMeaning in this workflow
Message / eventA small JSON letter sent between programs. A command asks for work; an event reports an outcome.
Producer / publisherThe sender: CRM publishes the command; payment-server publishes the result.
ConsumerThe receiver that opens the letter and does work.
ExchangeRabbitMQ's sorting desk: it directs a message to one or more queues.
Routing keyThe address label, here an event type such as invoice.generate.
QueueThe waiting tray where messages remain until a consumer handles them.
BindingThe sorting rule connecting an exchange + routing key to a queue.
Payload / envelopePayload is business data; the envelope adds IDs, type, version, source, and time.
Correlation IDThe return-address sticker: it links a result to CRM's original command.
Acknowledgement (ack)The consumer saying “I finished with this copy; RabbitMQ may remove it.”
RetryAnother attempt after a temporary failure. This command path waits 10 seconds.
Dead-letter queue (DLQ)The problem tray where unprocessable messages are retained for investigation.
OutboxA database table holding an outgoing event until it is safely published.
InboxA database table of received event IDs, used to ignore repeated deliveries.
IdempotencyDoing an accidental repeat has the same lasting outcome as doing it once.
Publisher confirmRabbitMQ accepted the message. It does not mean the other service finished work.
Not implemented / not foundNo card charge, gateway call, payment method, settlement, refund, or payment webhook was found in the reviewed source. An invoice with status generated is not evidence that money was collected.
